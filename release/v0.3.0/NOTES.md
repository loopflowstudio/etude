# v0.3.0

<!-- loopflow:release-notes=narrative;gate=safe -->

Etude v0.3.0 brings training, checkpoint evaluation and reporting into one experiment workflow: evaluate milestones as they arrive, see what has been delivered, and inspect the results without rebuilding a run's history. Across the cycle, rentals gain more provider choices and reuse more of the work already done on a machine, while storage failures and incomplete evaluations become visible. These notes cover the cycle since v0.2.0, including features released in the v0.2 patches; the behavior below reflects the later changes in that cycle. Before upgrading, check the launcher database and evaluation API changes in the operational notes.

## Follow training from the first checkpoint to the report

An experiment file now connects the jobs it launches, the evaluations it requests and the page that explains their results. Evaluation no longer needs a separate hand-maintained list of checkpoints and completed matchups. ([#39](https://github.com/loopflowstudio/etude/pull/39), [#49](https://github.com/loopflowstudio/etude/pull/49), [#28](https://github.com/loopflowstudio/etude/pull/28))

- **Try the whole experiment before renting.** `etude smoke FILE.py` runs each job's declared tiny form, then evaluation and reporting locally, and exits with status 1 on the first failure. Jobs declare that form through `Job.smoke`. `etude launch --smoke`, `queue --smoke` and a launching `etude eval --smoke` submit nothing if the smoke run fails. ([#96](https://github.com/loopflowstudio/etude/pull/96))
- **Evaluate while training continues.** Every checkpoint recorded by tracking is published while the run is going. An experiment's `eval(state)` selects work from the stored training state, and `etude eval` plays or launches matches that have not been delivered. Observed checkpoints include their save time as `wall_ms`. ([#32](https://github.com/loopflowstudio/etude/pull/32), [#39](https://github.com/loopflowstudio/etude/pull/39), [#86](https://github.com/loopflowstudio/etude/pull/86))
- **Compare meaningful training milestones.** Seatings express comparisons with earlier, fractional, fixed, final or job-aligned checkpoints and schedule games as checkpoints arrive. Positions are exact by default; `at_or_before=True` accommodates irregular saves, and `trained=True` excludes initial weights. Curves show a score or explain why it is missing. This is the final workflow for comparisons such as a checkpoint against its half-trained self, which earlier patches introduced as report-side opponent rules. ([#65](https://github.com/loopflowstudio/etude/pull/65), [#99](https://github.com/loopflowstudio/etude/pull/99))
- **Wait for capacity without duplicating evaluation work.** `etude eval EXPERIMENT.py --pool mini --queue --watch 60` queues requested jobs when the chosen machines are occupied. Queued matches remain in flight across passes. Immediate launch remains the default; a controller or `etude wait` drives queued work. ([#56](https://github.com/loopflowstudio/etude/pull/56))
- **See progress and retain partial results.** Launched evaluations report matches played, recent pace and time left, with output readable during the run. Partial results are marked as partial, and an early-ending attempt keeps its reported outcome and delivered evidence. A match returning no rows now fails with `match_has_no_rows` instead of appearing successfully done. ([#87](https://github.com/loopflowstudio/etude/pull/87), [#97](https://github.com/loopflowstudio/etude/pull/97))

## Read the experiment you meant to compare

`etude report PATH` draws an experiment's evaluations, performance and ML details as a self-contained HTML page; a folder produces experiment pages and an index. Later changes make selections, provenance and refresh behavior explicit, so the page stays useful as an experiment grows. ([#28](https://github.com/loopflowstudio/etude/pull/28), [#90](https://github.com/loopflowstudio/etude/pull/90), [#98](https://github.com/loopflowstudio/etude/pull/98))

- **External checkpoints can form learning curves.** `CheckpointRef.at` supplies clock positions and `line` identifies the learner. Evaluation-only experiments can draw a curve per learner without a tracked training run; these fields do not change player or match identity. ([#55](https://github.com/loopflowstudio/etude/pull/55))
- **Each chart compares its selected results.** Curves can combine match selections and name a job, counting overlapping matches once. Scientific inference variants remain distinct from execution provenance; ambiguous variants are explained rather than averaged. A job is one launch name plus one config, with seeds, devices and commits pooled as provenance. A launch name addresses all its config jobs. ([#90](https://github.com/loopflowstudio/etude/pull/90), [#98](https://github.com/loopflowstudio/etude/pull/98))
- **Refresh when needed.** Served pages retain the last generated report until **Refresh** is clicked; `--watch` enables periodic updates. Refresh reloads edited helper modules across the repository. If generation fails, the last successful page stays visible with the error. ([#90](https://github.com/loopflowstudio/etude/pull/90), [#98](https://github.com/loopflowstudio/etude/pull/98))
- **Read only what the page draws.** `Report.other_metrics` now defaults to `False`. Builds read the metrics and tables named by their panels, and rebuilding unchanged runs downloads almost nothing. ([#93](https://github.com/loopflowstudio/etude/pull/93))

## Keep long histories and repeated work affordable

The cycle reduces repeated work at several levels: storing evaluation results, reading reports, delivering files and preparing another attempt on the same machine. The shared artifact cache verifies content so reuse does not mix different versions of the same address. ([#63](https://github.com/loopflowstudio/etude/pull/63), [#51](https://github.com/loopflowstudio/etude/pull/51), [#54](https://github.com/loopflowstudio/etude/pull/54))

- **Evaluation storage scales by blocks.** Runs seal staged results into Parquet blocks instead of separate files for every match and table, with precomputed rollups for frequent summaries. `statsdb` keeps an experiment's query database and catches up when opened. `estimate` computes multiple rates and their intervals with one shared bootstrap; repeated selections reuse bootstrap draws without changing the estimates. ([#63](https://github.com/loopflowstudio/etude/pull/63), [#34](https://github.com/loopflowstudio/etude/pull/34), [#68](https://github.com/loopflowstudio/etude/pull/68), [#71](https://github.com/loopflowstudio/etude/pull/71))
- **Log result tables as rows.** `run.log_table(name, rows, **clocks)` avoids a separate metric name for every matchup. `RunData.read_table` applies the same supersession rules as scalar metrics. Index refreshes no longer reread permanent blocks, though adding a block still rewrites the accumulated manifest. For analysis, `etude.train.read.read_batches` streams selected metrics on one clock, holding one batch's arrays plus metadata per block. ([#91](https://github.com/loopflowstudio/etude/pull/91), [#95](https://github.com/loopflowstudio/etude/pull/95))
- **Reuse verified files and prepared environments.** Reports, tracking and jobs share one artifact cache. Attempts on the same machine link held inputs read-only, and a job's `prepare` step can be reused while its key holds. Evaluation orders matches to reuse loaded checkpoints and partitions split holds into contiguous runs of that order. ([#51](https://github.com/loopflowstudio/etude/pull/51), [#54](https://github.com/loopflowstudio/etude/pull/54), [#53](https://github.com/loopflowstudio/etude/pull/53))
- **Deliver new bytes instead of the growing history.** Attempt logs are published as immutable appended pieces. Author files under a run's `artifacts/` are immutable: write each once, named by content, and delivery will not reread it on later passes. Final output delivery transfers up to eight independent files concurrently, retaining completion until delivery succeeds and keeping successful immutable uploads for retry. ([#38](https://github.com/loopflowstudio/etude/pull/38), [#43](https://github.com/loopflowstudio/etude/pull/43), [#59](https://github.com/loopflowstudio/etude/pull/59))

## Use more machines without losing track of the rental

Vast.ai and Lium join RunPod in the existing launch, queue, wait and fetch workflow. Longer rentals, shared machine capacity and conservative recovery make provider choice useful without treating an uncertain response as proof that work or billing has ended. ([#79](https://github.com/loopflowstudio/etude/pull/79), [#83](https://github.com/loopflowstudio/etude/pull/83), [#84](https://github.com/loopflowstudio/etude/pull/84))

- **Choose GPUs and concurrent runs separately.** `--gpu-count` selects GPUs per machine across all three providers. Pools and on-demands accept `--slots N` to run up to N runs on each machine, sharing its GPUs and CPUs; cost is split by their overlapping time. The default remains one slot. ([#83](https://github.com/loopflowstudio/etude/pull/83), [#85](https://github.com/loopflowstudio/etude/pull/85))
- **Use R2 and longer storage grants.** Cloudflare R2 is supported alongside S3 for launcher and tracking storage. The fixed roughly 12-hour rental cap is gone: rentals are bounded by configured hours, budgets and price ceilings, and by storage grants of up to seven days on R2 or 36 hours on S3. ([#33](https://github.com/loopflowstudio/etude/pull/33), [#46](https://github.com/loopflowstudio/etude/pull/46))
- **Continue bucket-held work on SSH hosts.** The controller relays checkpoints to machines without access to the holding storage, including storage-less SSH hosts. An input that cannot arrive ends the attempt as `input_undelivered`, with a reason, instead of consuming repeated setup attempts. ([#77](https://github.com/loopflowstudio/etude/pull/77))
- **Recover conservatively.** A short Vast outage no longer causes immediate destruction of the rental and its disk; unhealthy observations open a durable outage record. A lost create that never produced a machine is recorded as never acquired at its deadline or on termination, costing nothing and releasing its machine slot. Vast's reported daily charges are not treated as a settled bill without authoritative billing coverage. ([#84](https://github.com/loopflowstudio/etude/pull/84), [#75](https://github.com/loopflowstudio/etude/pull/75), [#82](https://github.com/loopflowstudio/etude/pull/82))
- **Make delivery failures visible.** Storage requests time out and report `StorageUnavailable`; later delivery passes retry retained files. Status shows the age of the last confirmed delivery. Final rental delivery includes the last output before deletion, and large multipart fetches retain transfer accounting on the database-owning thread. ([#92](https://github.com/loopflowstudio/etude/pull/92), [#49](https://github.com/loopflowstudio/etude/pull/49), [#70](https://github.com/loopflowstudio/etude/pull/70))

## Operational notes

- **Launcher databases are not migrated.** The in-place upgrade path introduced earlier in this cycle was subsequently removed. The v0.2.16 schema change moved to version 14 and refused older databases. Preserve an older database and its compatible Etude installation if you need its history; move the incompatible database aside before starting a fresh one. Do not rely on the upgrade promise in the v0.2.12 notes. ([#73](https://github.com/loopflowstudio/etude/pull/73), [#94](https://github.com/loopflowstudio/etude/pull/94))
- **Update evaluation code using the old vocabulary.** `Agent`, `AgentKey` and `agent(...)` were replaced by `Player`, with `Model` for a checkpoint plus `Inference`, and `Code` for a code player. Existing recorded keys still load without replaying results. Update old `play` functions and query code. In older tables, Etude's `player` column reads as `seat`, and a neighboring game-specific `seat` reads as `game_seat`; new rows containing `player` are refused with `column_name_refused`. ([#57](https://github.com/loopflowstudio/etude/pull/57), [#60](https://github.com/loopflowstudio/etude/pull/60), [#61](https://github.com/loopflowstudio/etude/pull/61))
- **Name the storage provider explicitly.** `etude storage add` requires `--provider`, and Python `Storage` requires `provider`. R2 launcher access uses `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` and `R2_API_TOKEN`; tracking uses the first three. ([#33](https://github.com/loopflowstudio/etude/pull/33), [#35](https://github.com/loopflowstudio/etude/pull/35))
- **Reads no longer advance the controller.** `etude status`, `etude logs` and `etude usage` answer from the retained database without network or provider credentials and report freshness. Run `etude controller run` or `etude wait` to advance work; `etude logs --follow` obtains live output. ([#67](https://github.com/loopflowstudio/etude/pull/67))
- **Resume from the position actually restored.** `track(..., resumed_at=)` accepts declared clock coordinates when restored state differs from the latest checkpoint. Without it, the latest checkpoint remains the cutoff for superseding earlier attempt rows. ([#40](https://github.com/loopflowstudio/etude/pull/40))
- **Storage timeout settings belong on the controller.** `ETUDE_STORAGE_TIMEOUT_SECONDS` and `ETUDE_STORAGE_BYTES_PER_SECOND` propagate to workers; setting job variables alone does not configure the parent uploader. The default socket allowance is 60 seconds, with size-based extra time for whole-body uploads and enclosing deadlines still binding. Process exit can still take minutes while boto3 transfer threads finish after `finish()` returns. ([#92](https://github.com/loopflowstudio/etude/pull/92), [#94](https://github.com/loopflowstudio/etude/pull/94))
- **Reservations are not final bills.** Lium reservations account for price-change tolerance and its whole-hour fallback timer. A short job may reserve a whole hour without extending its execution deadline; that reserve is not a billing minimum. ([#83](https://github.com/loopflowstudio/etude/pull/83))

## Small changes

- Dense curves now mark isolated points that would otherwise have no visible line segment. Empty-evaluation messages name the experiment file once. ([#66](https://github.com/loopflowstudio/etude/pull/66), [#50](https://github.com/loopflowstudio/etude/pull/50))
- Dependency and GitHub Actions updates landed together, including mypy 2.4.1, Pydantic 2.14.3, Typer 0.29.1 and Ruff 0.17.5. ([#100](https://github.com/loopflowstudio/etude/pull/100))
- Contributor guidance forbids deliberately induced CPU, memory, disk or network pressure in tests, debugging, benchmarks and demos, and describes controlled alternatives. ([#52](https://github.com/loopflowstudio/etude/pull/52))
